# ADR 0004：接收端确认上传

日期：2026-11-23；状态：采用。

上传使用本机不可变快照与同一 manifest v1。发送端通过 HTTPS 请求会话，Agent 同时检查该身份的 upload_share_ids 和共享的 writable；SSH 的 NTFS 写入权限继续独立管理。
相同身份和 request_id 幂等绑定同一内容、共享与目标。会话 ID 不替代身份凭据；其他身份即使具备相同共享上传授权，也不能读取或操作该会话。

接收 Agent 在授权共享内创建随机会话暂存路径，检查可用容量，SQLite v2 保存上传会话及确认块。SFTP 只能写既有会话文件，客户端不使用创建/截断远端路径的操作。
发送端写完块并关闭 SFTP 文件后调用确认接口；接收端重新读取该范围计算 SHA-256，同步接收文件后提交确认事务。客户端显示接收端确认的进度，不把写入返回值当作完成证明。

恢复时查询接收端重新核验的确认集合，撤销磁盘损坏范围；丢失的 HTTP 确认响应不会导致接收端已确认块丢失。每次重试前等待旧 worker 停止，沿用任务管理器的写入所有权规则。

finalize 等待全部确认块，再在接收端重新读取完整文件并同步。发布使用 os.Root.Link 在授权根内原子建立禁止覆盖的正式文件名，然后移除暂存名；两者在同一卷且正式名出现时字节已经完整。
publishing 状态下重启，仅在目标与暂存指向同一文件或暂存已移除、且全文件哈希正确时对账完成。外部同名内容不能因字节相同被冒认。
采用根目录句柄约束路径解析，避免以“先检查再用绝对路径重命名”替代授权根约束。发送端只有收到接收端 completed 和匹配的全文件哈希才结束任务。

HTTP 只传清单与控制信息，文件字节仍走 SFTP。全文件 finalize 控制响应单独允许最多十分钟；普通控制请求继续使用短超时。磁盘不足 HTTP 507 与授权/完整性错误直接失败，不进行网络退避。

当前上传目标是单级文件名；目录级目标、空目录与路径策略在 P2.3 扩展。容量检查不能预留其他程序会消耗的空间，写入/同步失败仍必须停止，不能发布半成品。
