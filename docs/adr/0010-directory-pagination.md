# ADR 0010：目录游标分页和变化检测

- 日期：2026-11-24
- 阶段：P2.9
- 状态：已实现，验证范围见 [P2.9 验收](../validation/P2.9-directory-pagination.md)

## 问题

原 `entries` 接口仅支持一次读取 1000 项，目录稍大即返回 413。简单使用数字偏移，在连续两页之间插入或删除项目时可能重复或遗漏；只记最后文件名也可能漏掉插入在它之前的名称。

## 决定

保留受认证 HTTPS、共享授权和路径约束；加入 `limit` 和 `cursor`，返回 `next_cursor` 和 `has_more`。默认每页 100 项，范围 1～500。普通文件与目录统一按名称 UTF-8 字节序排列，保留大小写，不使用本地化或自然数排序；链接与非普通文件仍不列出。

每页扫描并排序目录元数据，用名称、类型、大小、修改时间和目录修改时间生成 SHA-256 指纹。游标包含范围摘要、指纹和最后一个名称，并由当前 Agent 实例的随机密钥进行 HMAC-SHA-256 签名。游标不是凭据；每一页都必须通过原有 Token 和共享授权。跨目录、跨共享、篡改或旧实例游标返回 400 `invalid_cursor`；Agent 重启后从第一页重新读取。

分页间指纹不同、枚举时发现文件消失或目录时间变化，返回 409 `cursor_stale`。调用方丢弃此前页面，从第一页重新开始；不悄悄拼接不同遍历结果。`EntriesAll` 和 CLI `--all` 仅在完整成功时返回聚合结果，遇到变化向上报告，不自动无限重试。客户端检查响应范围、页长、游标进展、名称顺序，并拒绝跨页重复。

采用无状态游标而非长期保存服务器快照，可避免快照缓存、过期清理和并发租用引入额外状态。代价是每一页都会重新扫描目录，时间约为 O(n log n)，内存为 O(n)；每页扫描最多 100000 项，超限仍明确返回 413 `directory_too_large`。扫描按批次读取并检查请求取消。该扫描上限与目录包传输的 10000 项限制互相独立。

## 一致性和兼容边界

普通文件系统枚举不是事务快照；并发写入可能发生在两次元数据读取之间，同名替换且恢复相同元数据也无法据此区分。这里提供变化检测和重读语义，不保证检测所有并发变化，更不把目录元数据哈希当作文件内容 SHA-256。传输依然依赖不可变 manifest、块校验和全文件校验。

API 路径保留 `v1`，控制契约修订为 `0.3.0`，能力列表加入 `list_entries_paginated`。首次请求也只返回一页。旧客户端严格拒绝未知字段，不能承诺与新版 Agent 兼容；同批升级 Agent 与客户端，调用方必须消费 `has_more`，或使用 `EntriesAll`。本阶段仅更新控制接口、Go 客户端和 CLI，不添加桌面目录浏览入口。
