# ADR 0012：桌面配对向导与请求绑定的单文件包

- 日期：2026-11-24
- 阶段：P2.11
- 状态：实现与范围见验收记录

将 P2.10 Go 资料核心直接桥接到 Wails `App`，客户端以四步向导读取本机地址、生成公开请求、检视回应、显式确认可信指纹后导入并保存设备。真实网络准备作为设备页的下一步，不能把本地资料验证显示为网络验收通过。

`.hopsend-pair` 沿用回应 ZIP 三个材料，SSH 主机公钥包含在 `device.json`，客户端根据它生成 known_hosts。已有协议不要求传私钥。源设备必须先取得目标客户端的请求和公钥，再授权和导出对应包；仅由 agent-init 生成一个无目标授权的通用包无法完成 SSH 身份绑定，因此不自动从通用初始化命令授予访问。

检视阶段仅使用包内自报指纹检查结构，返回 `trust_verified=false`。界面要求通过可信渠道核对、手填完整 SSH 和 CA 指纹并勾选。正式导入继续检查独立期望值、请求和私钥，绑定检视时的包哈希，拒绝检视后修改。设备使用请求 ID，重复导入不新增。新包更换时清除确认，预览有期限。设备列表原子替换及失败保留原列表沿用已验证的 P2.8 Windows 实现。

重新导出原公开请求须核验原私钥和当前本机地址。源端重试可能产生格式不同而字段完全相同的 device.json，比较全部 DTO 字段的语义；CA 和 Token 仍按字节固定，任何字段、凭据或身份变化均不接受为同一信任。

桌面统一处理原生拖放，配对扩展名优先，混合配对包/上传内容拒绝，普通 ZIP 不自动当作配对包。文件选择器继续接受旧 ZIP。这样不会为配对注册第二个全局回调并破坏上传的拖放。

源设备图形准备编排复用 P2.8，预览包自动检查依赖并申请 UAC，所有者明确确认后安装/配置。Tailscale 登录、标准账号和系统授权仍需要本人；发现设备不授予访问。这些源端分发代码和干净系统验收保留原 P2.8 范围，不随独立客户端 PR 宣称整阶段完成。
