# ADR 0011：发送端配对资料业务迁入 Go

- 日期：2026-11-24
- 阶段：P2.10
- 状态：已实现，验收见 [P2.10](../validation/P2.10-native-pairing-materials.md)

## 问题与边界

P2.8 在线预览的发送端通过 PowerShell 生成 SSH 密钥、检查回应并导入信任。业务错误被脚本输出和退出码包裹，难以复用和区分阶段。P2.8 的完整干净系统验收仍未完成，不能把整套分发和在线 UI 当作本阶段的已验证前提。

本阶段先独立交付传输无关的资料核心及 CLI：请求生成、受限 ZIP/JSON 解析、身份与本机请求绑定、既有信任比较及原子导入。`contracts/pairing/v1` 固定资料格式，`internal/pairing/material` 处理业务，Windows ACL 通过原生 API 适配。核心不启动 PowerShell、Tailscale、SSH 或系统服务。接收端环境检查、用户确认、UAC、防火墙、计划任务和受控公钥安装继续留在原 P2.8 流程，不自动跳过授权。

## 决定

1. Go 直接生成 Ed25519 与 OpenSSH 格式私钥；请求只含公钥和设备信息。保留原 `trust/<request_id>/` 布局，兼容旧请求与回应。Windows 在创建暂存目录时设置当前账号和 SYSTEM 的受保护 DACL，再写入私钥；支持对原有账号所属目录做权限收紧，不接管其他账号的目录。
2. 回应 ZIP 总体最多 256 KiB、恰好三项，每项展开最多 64 KiB。拒绝重复、额外、越界和链接条目、CRC 错误；JSON 拒绝未知字段、重复键、字段大小写混用、额外对象和无效 UTF-8。CA 文件需为有效的自签 CA 公钥证书，元数据指纹必须匹配另行核对的期望指纹；不能把回应自报指纹当作独立信任来源。
3. 导入检查接收端 IP、固定端口、共享、账号、Windows 配置路径，并核验本机原请求的私钥与公钥匹配。在线调用方应同时传入目标 IP 和请求 ID；离线导入仍须找到本机原请求和私钥。
4. 同一请求使用 OS 文件锁隔离并发导入。新信任先写入同目录下受保护的暂存目录，对文件执行 Sync，再一次重命名发布完整 `paired/`。重试只接受相同的三个资料及一致的主机记录/连接引用，不覆盖旧信任。连接配置只存路径，不内嵌 Token 或私钥。
5. 业务错误返回稳定的 `stage/code/message`，不拼接原始凭据、私钥或未经筛选的脚本输出。`pair inspect` 只输出公开设备元数据，`pair import` 返回 `verification=not_run`；真实 HTTPS/SSH/SFTP 验收继续由 Go `device-prepare` 完成。

## 验证与限制

测试覆盖新旧格式互通、实际 Windows OpenSSH 密钥读取、WinPS5.1 生成 ZIP、重复导入、坏指纹/绑定/资料、私钥不匹配、取消、锁竞争、Windows ACL 和目录链接拒绝。既有信任发生变化时需要显式重新配对，不自动更新证书或主机密钥。

P2.8 工作树可直接接入 Go 核心，逐步去掉发送端的脚本调用；它的原生 UI、远端确认与新设备准备仍按自身验收门槛记录。本阶段不把接收端部署全部迁入 Go，不宣称完成机器级服务、跨平台应用或物理断电验收。信任目录须为本账号控制的本地目录；同卷重命名保证发布的可见性，不等于已验证所有文件系统和断电条件下的持久性。
