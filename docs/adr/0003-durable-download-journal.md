# ADR 0003：持久化下载与文件发布边界

日期：2026-11-23；状态：采用。

## 决策

下载引擎通过 Journal 接口保存任务，不依赖 SQLite 驱动。应用层使用纯 Go modernc.org/sqlite，保持 Windows 构建不依赖 C 工具链。
数据库启用 WAL、synchronous=FULL、外键和 5 秒忙等待；每个 Store 只有一个数据库连接。user_version=1 迁移在事务中创建任务与已确认块表，拒绝更高版本。

任务保存完整原始 manifest、源快照路径、绝对目标/暂存路径、状态以及源连接配置引用。只保存 CA、Token 文件、SSH 私钥与 known_hosts 的路径；不复制凭据内容。

目标同目录的持久锁标记由 Windows 独占内核句柄持有；进程退出自动释放，标记文件不删除，避免删除后其他进程取得不同锁对象。锁覆盖核验、worker、重命名和最终状态事务。其他类 Unix 平台使用 flock 适配，当前实测平台为 Windows。

块先 WriteAt，核验长度与流式 SHA-256，再同步暂存文件，最后事务提交已确认记录。进度只在确认成功后增加。任务重新启动时在没有 worker 的情况下逐块重读已记录范围；不依赖文件预分配长度。损坏、截短或丢失范围撤销确认后重新入队；未记录范围保守重传。

完整文件重新校验后先记录 publishing，再关闭文件并执行禁止覆盖的同卷重命名，最后记录 completed。若重命名后退出，重启时只在暂存已不存在、任务原状态为 publishing/completed 且目标完整哈希和长度正确时对账完成；暂存与目标同时存在一律报告冲突。

## 影响与边界

- 每块 Sync 和 FULL 事务有性能成本，先保证可恢复性，优化需独立测量。
- 重启需要读取已确认范围，避免将数据库状态当成磁盘内容证明。
- 故障注入使用独立进程在写入、Sync、事务、重命名附近直接退出；不将此结果描述为物理断电实测。
- 自动重试、暂停/取消语义和网络状态分类属于 P1.3。迁移与持久化不替代这些功能。
