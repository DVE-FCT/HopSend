# ADR 0015：上传目的父目录与恢复身份

- 日期：2026-11-27
- 阶段：P2.17
- 状态：已实现；实际验证及现场限制见 [P2.17](../validation/P2.17-upload-destination.md)

## 决定

`CreateUpload` 和 `UploadSession` 增加可选 `parent_path`。缺省/空串/`.` 表示共享根，线上统一为空串并省略字段；非根为规范 `/` 相对路径，每级遵循 Windows 安全名称规则，拒绝绝对路径、`..`、ADS、链接/重解析点和保留的 `.hopsend-uploads` 临时区。`target` 继续是单级名称。新能力名 `upload_parent_path`；客户端给旧 Agent 只能创建共享根上传，非根明确拒绝，不悄悄降到根。

会话在 SQLite v3 固定父目录路径及共享根/父目录文件系统身份。每次幂等重取、查状态、确认块和 finalize 都重开并核验身份。父目录删除、重建、被链接替换或配置指向其他根均拒绝原会话；不创建缺失父目录，不自动接受新目录。Windows 在控制请求期间持有目录链的禁止删除/重命名句柄，覆盖校验、哈希、同步和同卷发布，防止在校验之后替换目录。文件字节仍经 SFTP。

暂存仍位于共享根内 `.hopsend-uploads/<session>/`，所有状态、块确认及最终发布与固定父目录绑定。这样父目录在两次控制请求之间变化时，SFTP 不会经那个父路径写到其他位置；下一次确认拒绝，正式文件不发布。根和父目录都不允许跨卷的重解析点，故暂存与目标仍同卷。临时区与用户正式目录分离，不放宽 SSH 或 Agent 的权限。

SQLite v2 没有记录目录身份，无法补造此前的证明。升级保留旧记录和文件，但对缺少绑定的旧会话返回明确错误，要求源/接收所有者核对后以新的目标或任务重建；不能自动冒认。旧客户端对新 Agent 的新根目录上传保持无新字段的 wire 形状。v1/v2 升级先用 SQLite `VACUUM INTO` 生成包含已提交 WAL 的一致备份并同步，再以排他写事务迁移。旧程序不能打开 v3 数据库，回退须停止相关程序并使用匹配版本及 `.pre-v3-*.bak` 备份，不删除或静默改写状态。

## 桌面与验收

上传目录选择复用 P2.15 浏览模型/组件；只有读写共享展示目录树，只写共享只提供受约束的相对路径输入，不能获得读取权。共享根为默认。创建后父目录进入任务目标身份和恢复源引用，切设备/共享使旧目录选择失效。

验收包括嵌套中文、根兼容、只写、同名冲突、目录/空文件、父目录删除/替换/链接、暂停/重启恢复、旧 Agent 和旧数据库策略，以及最终哈希与发布位置。正式目录创建、批次上传与机器级服务属于后续阶段。
