# ADR 0013：显式轮换信任与不可变凭据版本

- 日期：2026-11-25
- 状态：采用
- 阶段：P2.13

## 问题

远端重装、SSH 主机密钥更新或 CA 重签后，普通 ImportReply 必须继续拒绝 trust_conflict。但删除设备重建会丢失稳定设备身份；把 paired 目录改名并原地发布新资料，会使 SQLite 中已经保存的绝对凭据路径读到新的身份。

## 决定

客户端通过显式 RotateDeviceTrust(id, reply, expectedSSH, expectedCA) 轮换。新回应必须属于该设备的原 RequestID 和本机私钥；先检视并独立核对完整 SSH/CA 两项指纹，再使用同一材料校验管线。发现、健康和普通导入均不能触发轮换。

material.StageTrustRotation 与 ImportReply 共享验证、账号 ACL、导入锁、文件同步、暂存和完整目录发布；仅发布目标不同。首次资料仍位于 trust/<RequestID>/paired/；新版本位于同级 paired-<SHA256>/。版本摘要覆盖规范设备字段和准确 CA/Token 字节，不依赖 ZIP 或 JSON 排版。相同资料重复使用同一个版本，已有版本被改坏时拒绝覆盖。

新目录完全落盘后，桌面以已有设备快照为前提执行比较后更新，原子替换 devices.json，成功后更新内存。用户并发编辑导致快照变化则拒绝提交。设备 ID、本机私钥、用户设备名和 manage_agent 选择不变。首次配对用“记录不存在”为前提，避免覆盖期间新出现的设备记录。普通导入也不得把已轮换设备引用退回首次版本。

失败或进程退出发生在设备指针提交之前，当前设备和旧目录仍有效；新发布但未选中的版本可安全留待重试。指针提交之后，重启读取完整新快照。采用不可变版本避免双重目录重命名之间的空窗，无需移动旧凭据才能回滚。不会在网络验证失败时自动回退信任，这可能重新接受已撤销身份；网络结果单独报告。

## 任务语义与限制

轮换只改变该设备后续新连接使用的凭据路径，不修改任务表、任务 ID、状态、清单或 Source。活跃/暂停任务继续固定旧路径；远端撤销旧 Token/证书/SSH 授权后，旧任务可能无法恢复，不能自动替它接受新身份。任务凭据迁移需未来单独的显式操作和验收，本阶段没有实现。

本阶段复用客户端原公钥，不轮换 SSH 客户端私钥，不自动续签远端证书，不撤销远端旧 Token/公钥，不恢复损坏的旧 paired 目录。源电脑必须提供与原请求绑定的新回应。远端地址、账号、共享和配置路径仍在预览中展示，需要所有者确认。

保留所有旧版本和发布未选中的版本，不自动清理可能被任务引用的目录；缓存生命周期仍属于 P4.2。摘要不包含明文凭据，日志和导出只记录引用。多桌面实例同时修改同一数据目录不在当前验收范围。

## 验证

覆盖错误指纹/请求绑定、普通导入冲突、重复轮换、格式重编码、取消/锁冲突、Windows 私密 ACL、新版本损坏拒绝、清单写入失败的旧快照保留、并发快照变化拒绝及 SQLite 任务引用不变。见 [P2.13 验收](../validation/P2.13-trust-rotation.md)。
