# ADR 0016：共享源快照的独立批次上传

- 日期：2026-11-27
- 阶段：P2.18
- 状态：已采纳

## 版本与授权

一发多收创建多个独立上传会话，最多32个接收目标。一次显式选择只生成一份只读对象和一份源 manifest，所有任务使用完全相同的 ID、块边界、哈希和内容版本，源之后变化不进入批次。

v1 manifest 的 share_id 原用于目标共享，不能为每个接收端静默改写清单。新增可选 `manifest_scope: source_snapshot` 与能力 `upload_source_snapshot`：这个显式模式下 manifest 中 share_id 仅是源快照命名空间，目标由请求的 share_id / parent_path / target 单独授权并固定；默认模式仍要求清单共享与目标共享相等。接收端校验原 manifest 的完整 ID/哈希，不把源命名空间当目标权限。响应、SQLite 和恢复记录保存 scope；旧 Agent 对此模式明确拒绝。

## 持久化与调度

SQLite schema v4 记录批次、每个接收任务、固定连接引用和快照引用。请求键支持重复提交去重，改变目标或源路径必须新建批次；不自动重发已成功的任务。准备串行且受进程/文件锁控制，不建立无界源复制队列；批次最多32目标，批次队列最多2个活动接收任务、全局4个活动上传块、同节点2块。快照创建前估算磁盘预算并检查容量；目录包同时预留打包和对象副本空间。

每个任务的失败、取消和接收端权限相互独立。失败/暂停保留快照引用以便恢复；完成或取消必须等待旧 writer 退出后才释放其活动引用。活动引用归零标记为可清理候选，实际副本仍保留供历史对账与将来的显式引用清理，P2.18不自动删除用户数据、其他任务正在使用的对象或未知缓存。

关闭桌面先停止批次调度、暂停并等待活动任务，重新打开后队列保持暂停，用户显式恢复。按批次全部暂停/恢复/取消与逐台控制共用同一调度状态。已经完成的接收端不会因批次恢复再次发送；一次失败不取消其他目标。任务列表按批次分组，显示每台的目标、状态与进度。

## 验收

真实本机两个以上独立 Agent/SFTP 端点验证不同授权共享、相同 manifest/对象；离线/拒绝/同名冲突和成功并存；源变化不混入；逐台/批次暂停取消和重启恢复；引用计数不提前释放；并发和准备预算有界。自动化双端点不冒充两台物理设备现场；P2.8现场和P3物理源门槛保留。
