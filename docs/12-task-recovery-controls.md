# P1.3 任务控制与网络恢复

## 当前实现

Go 应用层 Manager 管理实际任务执行、实时状态、暂停、继续和取消；CLI 与后续 Wails 共用此层。
暂停/取消先触发上下文取消、关闭 worker 的 SSH 连接，等待全部 worker 及目标锁释放，再持久化并通知最终状态。
发布已成功时保留 completed，不因同时到达的暂停请求误报取消。

暂停保留已确认块和暂存文件。取消也保留数据供用户后续清理，普通 resume 不会重新启动已取消任务；显式 download 表示重新发起。
控制方法只控制本进程的执行者；跨进程竞争仍由目标内核锁拒绝，不用删除锁文件或直接改数据库代替控制。

## 自动重试

CLI download 默认重试 6 次，初始退避 1 秒，逐次翻倍，上限 30 秒；可设置 `--retries 0` 禁用，支持 0～100 次和不超过一分钟的 `--retry-delay`。
每次尝试返回前引擎已等待旧 worker 退出并释放写入锁；下一次从同一原 manifest 和 SQLite 记录重核验。

网络连接失败、连接超时、SFTP 的 connection lost/no connection、HTTP 408/429/5xx 可重试。
TLS 证书/主机名、SSH 主机信任和鉴权、API 401/404、路径/磁盘、清单版本和块哈希错误直接失败，不能以无休止重试掩盖。
重试耗尽会返回失败并保留续传状态；不宣称永远自动重连。

等待网络时可暂停/取消，退避计时立即响应。恢复后的有效进度按重新核验结果计数，重传不重复增加确认字节。
`--read-timeout` 是持续无数据进展的时长，默认两分钟；有数据持续写入时刷新计时，允许慢链路用更长总时间完成一个块。SSH 握手与 HTTPS 请求仍有独立、有界超时。
进程刚启动的 rechecking 阶段不把尚未读取核验的记录直接当作有效进度。

## CLI 本地交互控制

先从任务列表取得任务 ID，再在同一交互进程中继续：

```powershell
./hopsend-cli.exe control --database 'D:\HopSendData\tasks.sqlite' --task '64位任务ID'
```

stdin 接受下列单行本地命令，绝不作为远端 SSH 命令执行：

| 命令 | 行为 |
|---|---|
| pause | 等待执行者退出并保存已暂停 |
| resume | 使用原 manifest 继续已暂停任务 |
| cancel | 等待执行者退出，记录已取消 |
| status | 输出本进程最近真实状态 |
| quit / 输入结束 | 暂停本进程剩余任务并退出 |

普通 download / resume 仍适合自动化，使用 Ctrl+C 可停止并保留恢复状态。
control 只用于已有任务；桌面端将通过绑定方法创建并控制任务，不模拟进度。

## 验证范围

实际 SSH/SFTP 连接断开后进入 waiting_network，重新连接完成并保持文件字节一致；暂停返回后实际暂存文件和确认数保持不变。
测试还覆盖错误分类、有界退避、退避期间取消、重复执行拒绝和完成/取消竞争。
两设备不同网络结果另见对应阶段验收记录，不能用本机回环测试冒充。
