# 一发多收：固定一个版本，独立发送

在“传输任务 → 上传到设备 → 一发多收”操作：

1. 选择一个本机文件或文件夹，也可拖入一项。多个散文件先放到一个文件夹。
2. 勾选 1～32 台已配对的接收设备，分别填写共享 ID、已有父目录及接收文件名。留空父目录表示共享根，留空文件名沿用源名。
3. 有目录读取权时可点“浏览接收目录”。只写共享继续手工输入路径，不会获得读取权。
4. 点击“创建批次并发送”。本机先创建一次固定快照，之后各接收端独立排队、确认块和校验发布。源文件之后变化不会混入当前批次。
5. 在批次卡片查看逐台进度，使用逐台暂停/继续/取消或批次“全部暂停 / 全部继续 / 取消未完成”。成功的设备不会因继续批次而重发。

关闭应用会暂停队列并等待旧写入者退出；重新打开后主动点击继续。某台离线、拒绝授权或发生同名冲突，只影响该台。错误可跳转设备诊断；取消不是删除接收文件、撤销已完成传输或清理暂存。

接收 Agent 必须支持 `upload_source_snapshot`。子目录还须支持 `upload_parent_path`。缺少能力明确报错，请升级接收 Agent 后重试，不能悄悄改发根目录。P2.8 托管/分发预览与稳定 Agent 的包来源仍需区分。

## 容量、并发和状态

- 一批只生成一份源 manifest 和只读对象；不同目标共享也不改写 manifest。目标 share_id、目录、文件名及凭据各自固定授权。
- 单次准备上限按 64 GiB 初步估算，文件夹最多 10000 项，预留目录包与对象共存空间及 64 MiB 余量；准备期间空间仍可能被其他程序占用，发生写盘错误则停止，不承诺卷空间保留。准备是串行的，最多 16 个有活动快照引用的批次。
- 批次队列最多同时运行 2 个接收任务，每个 2 块；与单设备上传共用桌面进程全局 4 块、同一配置 SSH 地址 2 块预算。各 CLI/桌面独立数据目录间不协调全局带宽。
- 失败、暂停、排队任务保留快照引用；完成/取消在 worker 退出后释放引用。同一个快照被多个批次使用时合计引用。引用归零只标记候选，磁盘副本和历史继续保留；自动垃圾回收属于后续清理功能。
- 重试创建沿用请求键，不会重新复制或重复创建。同版本同目标已有批次时拒绝重建重复任务；如需另发，请选择不同目标。历史目前最多读取 1000 批，超出返回明确错误，不返回截断结果；尚无历史归档界面。

## 升级与边界

SQLite 升级到 schema v4，迁移前用 SQLite 一致备份保存 `.pre-v4-*.bak`，包含已提交 WAL。旧程序拒绝 v4；如需回退，应先退出所有相关进程并保留当前库及 WAL，用核对过的升级前备份恢复，新增批次不会出现在旧版本中。不得直接用旧程序打开新版任务库，也不要删除仍被恢复任务引用的对象或凭据。

本阶段为多个独立上传任务，HTTPS 协调元数据，SFTP 传字节，Tailscale 承载连接。没有广播上传协议、多源下载、远端创建目录或机器级服务。验证范围见 [P2.18 验收](validation/P2.18-batch-upload.md)。
