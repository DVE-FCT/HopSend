# 共享目录浏览

P2.15 提供桌面只读目录浏览，复用 P2.9 的认证分页接口。它不根据目录名称或大小猜测内容版本，暂不提供点选直接下载；路径版本索引与下载闭环属于 P2.16。

## 当前用法

1. 打开“传输任务 → 从设备下载”，展开“浏览共享目录”。折叠时不发出目录查询；展开后读取已选设备的授权共享。
2. 选择设备及共享。列表显示名称、类型和大小；点击目录进入，面包屑可返回根目录或上级。空目录明确显示为空。
3. 每页加载 100 项，点击“加载下一页”追加；文字仅显示已加载数量，不把当前页当作完整目录。读取结束后显示结束标志，最多缓存 100000 项，列表区域可滚动。
4. 点击文件只显示相对路径、大小和当前缺少内容版本的说明。真实下载继续使用下方清单 ID 与本机保存位置；浏览不触发发布、哈希、SFTP 或新传输任务。

“刷新共享”重新查询权限和共享列表；“重新读取目录”从当前目录第一页重读。游标过期或目录变化会清空旧页面，要求重新读取，避免拼接不同时间的目录列表。

## 权限与连接

HTTPS CA、Token 和既有共享授权照常验证。只读或读写共享可以浏览；仅上传（write_only）共享可显示在授权列表中，但无法列目录。它不会因此获得读取权限，也不向客户端公开宿主机绝对共享路径。

浏览器不自动部署或启动 Agent。查询失败时，托管设备提供“准备并验收设备”，只有主动点击才运行现有管理流程，成功后重新读取；非托管设备需所有者升级/启动。两者都有“诊断此设备”入口。旧 Agent 缺少 list_entries_paginated 能力时明确提示升级，不退回可能截断的旧接口。

每次后端查询总预算 15 秒。切换设备、共享、目录、更新设备凭据或收起/离开组件后，旧请求结果不再更新列表；已发出的 HTTPS 请求仍按后端超时释放。重复点击下一页不会并发追加同一页。

## 接口与边界

Wails 的 App 方法：

```go
BrowseDeviceShares(id string) (app.BrowseSharesResult, error)
BrowseDeviceEntries(id, share, path, cursor string, limit int) (app.BrowsePageResult, error)
```

App 只传 Agent HTTPS 配置给共享应用层，不传 SSH、管理脚本或本机源文件。业务响应保留结构化错误码（例如 cursor_stale、browse_denied、browse_unsupported），不把失败结果作为空目录。前后端都检查页范围、名称顺序、重复项、游标进展与路径约束。

此阶段未改变 Agent 协议：共享枚举不是事务快照；列表元数据不能证明文件内容未变。每页仍有 Agent 的扫描/排序成本。100000 项为有界限制，实际测试规模为 1005 个文件加一个子目录；没有宣称超大目录渲染性能或其他系统支持已通过。

上传目标目录选择属于 P2.17；当前 Target 的单层名称限制保持。验收见 [P2.15](validation/P2.15-remote-browser.md)，后续依赖见 [实施计划](23-next-stage-plan.md)。
