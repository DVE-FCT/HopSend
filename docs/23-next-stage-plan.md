## P2.8：先补现场证据，不重做已存在入口

输入：完整版本包、所有者能现场确认的干净 Windows x64、同一 tailnet、标准账号和具备管理员确认权限的所有者。无需 Go/Node。新系统按说明解压到非 OneDrive 的受控目录；保留当前拒绝重解析点的限制，先不放宽。

验收顺序：

1. 记录 Windows/组件初始状态，确认未安装开发工具；包逐项校验。
2. 首次准备补齐运行依赖，Tailscale 由所有者登录，标准账号/管理员交接按真实界面完成；取消或失败不留下半授权状态。
3. 接收端从图形页读取请求、选定共享与上传权限、生成包；或使用 8 位码在线流程。客户端验证并保存，读取与确认上传各完成一项真实哈希测试。
4. 关闭桌面/SSH 管理会话后 Agent 继续健康；手动重启并登录后，不主动启动 Agent，验证任务、进程版本/路径和独立 HTTPS 健康。
5. 重复准备、拒绝授权、其他账号占用 Tailscale、端口冲突、升级失败回退及卸载保留用户资料分别记录。无法执行的项保留为待验收。

输出：补齐 P2.8 原验收文档和版本包证据，达到全部完成条件后统一提交，不能只因其他设备上通过部分检查就合并关闭。

## P2.15：共享目录浏览

前提：P2.9 API 和已配对节点，不依赖 P2.8 新系统验收完成。先完成只读浏览，给 P2.16/17 复用；不能把此阶段独立标作“点选即可下载”。

交付：Go 桌面方法读取授权 shares 和 entries 分页；一个可复用目录组件，支持共享切换、面包屑、返回上级、文件大小、下一页、空目录和重读提示。前端不调用 CLI，也不按本地文件对话框伪装远程目录。浏览与显式准备分开：节点未就绪时提供准备入口，后台浏览不部署、不生成文件快照。

验收：1005 项全遍历无重漏；分页期间新增/删除/改名/大小变化后按 cursor_stale 丢弃旧页；切换设备/共享/目录后，旧请求响应不能污染新列表。授权外共享、路径越界、符号链接/重解析点与旧 Agent 能力缺失显示明确错误。生产桥接、API 集成与实际桌面操作各自有记录。

## P2.16：选择路径后绑定内容版本并下载

P2.9 Entry 只有名称、目录标记和大小。Manifest 按 ID 提供，当前没有路径索引；相同文件名/大小无法证明内容版本。需要先立协议和 ADR，再实现索引及 UI，不能只自动填写一个猜测的 ID。

交付顺序：

1. 定义授权共享内的路径、文件/目录类型与不可变版本引用，契约不泄露宿主绝对路径。索引同时绑定版本内容和源信息，不能用 mtime/大小替代 SHA-256。
2. 源设备提供显式“发布此文件/目录”操作，生成快照和清单后原子更新路径索引。发布可取消、有资源和并发预算；源发生变化或索引失效时重新核验，不把正在改动的文件标为可信版本。完整源端图形发布依赖 P2.8 预览整合，核心可独立验证。
3. 客户端选择已发布路径后获取受认证版本，展示名称/大小/版本，再选本机目的地创建真实任务。未发布/版本变化显示原因与源端发布指引，保留手工 ID 兼容入口。仅浏览不触发大文件复制与哈希。

验收：同名替换、同大小不同内容、旧索引、目录变化、未授权路径、不可信 manifest、断网/取消/重启；中文、空文件和文件夹往返；最终 SHA-256、暂存/同步/事务/发布顺序仍满足原不变量。下载固定所选不可变版本，不因源后来更新而悄悄换版本。

## P2.17：上传目的目录

现状 createUpload 的 Target 经 SafeLeaf 验证，只能是共享根的单个名称。允许在 UI 输入 a/b 并不能实现安全嵌套上传。

先增加受认证、共享范围内的目标父目录字段，根目录为兼容默认值。上传会话持久保存父目录身份与最终 leaf；路径校验、临时写入、接收端确认、完整哈希与同卷发布共同绑定目标。恢复或 finalize 时重新验证父目录没有被链接或替换，目标冲突不覆盖。不在会话中接受客户端绝对路径。

UI 复用 P2.15 选择目录并显示现有内容。read_write 允许授权浏览；write_only 不提升为读取权限，显示只写限制并提供受控相对路径输入或根目录发送。新建远端目录是单独显式授权操作，未实现前不显示可用按钮。

验收：根/嵌套中文、已有同名文件/目录、父目录删除/替换、越界/重解析点、写满/拒绝权限、暂停恢复与最终发布位置；旧任务与旧 Agent 的兼容策略明确。

## P2.18：一个内容发送给多个设备

使用多个独立上传任务，不新增“广播式会话”。多选只是入口，还需有界准备队列、逐台权限检查、独立会话和状态、重复点击防护、全局网络与磁盘预算。

一次选定本机内容后固定同一内容版本。可复用本机只读快照，但引用计数和任务生命周期明确；一个任务完成/取消不能删除其他任务正用快照。若先采用独立副本，必须估算磁盘需求并说明限制，不无限复制大文件。

验收：至少两个接收端分别成功；一台离线/无上传权/同名冲突时另一台继续；所有成功接收端完整哈希一致；逐台暂停/恢复/取消及批次停止的语义清楚；创建失败不自动重发已成功任务，源变化不混入同一批次。

## P3.1 / P3.2：多源与调度

P3.1 前先固定内容版本比较规则。首版要求相同可信 manifest、内容 ID、总长度、块边界/块哈希和负载类型，不因多个源宣称同名文件就混读。每源使用独立已核对 HTTPS/SSH 资料和授权路径，且在领块前取得受认证清单。若未来允许不同 share ID 的等价内容，需要另行规范版本等价规则，不跳过校验。

增加全局/每节点预算及动态领块，先维持 32 MiB、节点 2、全局 4 作为待多源实测起点；记录每源真实字节、有效字节、CPU/内存/磁盘和总耗时。至少一客户端加两台独立源做物理验收；同机双 Agent 只能支持自动化功能测试，不能证明独立源网络收益。桌面明确展示所选多个来源和版本一致性结果。

P3.2 依次交付掉线重新分配、坏块节点隔离、慢节点处理、全局/节点/任务限流及有界设置。重分配前等待旧 worker 停止，块只有一个有效写入者；未确认块按整块重取。限流以实际字节生效，重传单独计量。局部块缓存是否立新阶段由重传浪费证据决定；采用前必须设计子块校验、落盘和版本引用，不能确认未经完整块验证的前缀。

## P4.1 / P4.2：性能边界、安装和清理

P4.1 紧接 P3.2：单源/多源、局域网直连/DERP、高延迟和丢包、长时间大文件的重复矩阵。保持环境、版本、缓存条件和实际字节口径可比较。磁盘满和崩溃注入使用专用小卷/虚拟机，覆盖暂存、Sync、SQLite、finalize 和发布；不填系统盘、不对用户设备断电，不把进程退出当作物理断电。

P4.2 覆盖普通用户安装、用户登录驻留与机器级服务边界、完整升级/回退/卸载、依赖来源/签名和跨版本恢复。凭据版本清理需先扫描所有任务 Source、设备当前引用、活跃/暂停任务和已发布未选中版本，展示大小/引用/保留策略；预览候选与确认删除分离，清理期间重新核对引用，拒绝链接与越界。没有充分证据的旧信任/Agent/暂存不得自动删。程序缓存、合成测试产物、凭据、任务库及用户正式文件使用不同清理规则。

## 阶段关闭与资源控制

每阶段功能、契约、测试、说明和真实验收统一形成可审查提交；测试分支 → PR → CI → 合并 → 回读复验，再清理旧分支。未能进行的物理场景写入阶段记录，不以绿 CI 代替。规划验收不声明这些未来功能已经实现。

开发默认小型可重复合成样本，5 GiB 测试只在需验证持续大文件/64 位边界时显式执行。验收后保留种子、长度、哈希、命令与结果，不长期堆积完整测试文件；删除前核对无活跃/可恢复任务依赖。分发通常保留最新版和上一版，其他直接引用版本保留或先迁移入口。2026-11-25 的人工清理不是已交付的产品缓存管理功能。
