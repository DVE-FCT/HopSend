# P2.3 文件夹与路径处理

## 当前路线

文件夹先生成不压缩的确定性目录包，再沿用同一清单、32 MiB 逻辑块、SQLite 续传和 HTTPS/SFTP 传输。
目录包包含完整相对路径、空目录、文件尺寸和逐文件 SHA-256 索引；manifest 的可选 payload_kind 为 folder。
下载端或接收 Agent 完整验证目录包，展开到目标旁的唯一暂存目录，逐文件同步，最后同卷禁止覆盖发布整个目录。
这里的分块续传作用于目录包；当前不支持目录中单个文件独立优先级或原地增量同步。

## 发布和下载

CLI publish 的 source 可以是文件夹，其他参数与普通文件相同：

```powershell
./hopsend-cli.exe publish --source 'D:\Share\项目资料' `
  --content-dir './identity/content' --share files --chunk-mib 32
```

从另一个设备 download 该 manifest_id，output 填写新的目标目录。桌面端也通过同一清单自动识别目录包，无需把目录当作 ZIP 手动解压。
已有目标目录一律拒绝，不合并、不覆盖，包括空的同名目录。

## 上传

CLI upload 的 source 可直接填写文件夹，target 是接收共享内的新目录名。
桌面上传面板可以选择文件夹。接收端仍需要 writable / upload_share_ids 与 SSH 写入权限；接收端校验及发布整个目录后才返回 completed。
包内每个文件也核对索引 SHA-256，重开完成任务时重新核验保留包与正式目录。

## 路径与异常策略

- 只允许正常文件和目录；符号链接、Windows junction/reparse point、设备文件、硬链接条目和越界路径拒绝。
- 相对路径最多 4096 字符，单级名字最多 200 UTF-16 单元；最多 10000 项。实际 Windows 长路径已验证超过 260 字符的中文层级。
- 拒绝重复/大小写冲突、盘符、ADS 冒号、反斜线、保留设备名、末尾点空格和协议保留索引名。
- 解包使用 os.Root 约束所有包内访问。索引位于包末尾且与实际条目、尺寸和哈希完全一致才允许发布。
- 新目标检查磁盘空间；目录接收需要同时保存包和展开内容，初始检查至少两倍包大小。容量可能被其他程序消耗，实际写入/同步失败仍会停止。
- 普通权限不足会返回错误，不修改系统安全设置；验证只在独立临时测试目录配置可恢复 ACL。

为支持发布边界和已完成目录的恢复对账，当前保留目录包缓存。下载端的该包仍使用任务保存的 .partial 路径，完成后不作为“未完成字节”计数；接收端保留在会话暂存数据区。
清理该缓存后不能继续用原任务做目录完整对账，应在停止任务后按明确数据保留策略处理；自动缓存回收属于后续产品完善范围。
目录源或结构在生成版本时变化会拒绝发布；原始目录后续变化不修改已经发布的快照。

## 真实验收范围

空目录、空文件、中文、超过 260 字符的路径、混合文件的实际 HTTPS/SFTP 上传/下载通过；目录发布前/后退出进程的恢复通过。
真实 Windows junction 和只读 ACL 的失败行为已验证。物理磁盘写满与断电没有执行；容量不足和进程边界均按明确测试方式记录，见阶段验收。
