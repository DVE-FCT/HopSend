# 已发布路径与版本下载

P2.16a 提供路径索引和源端显式发布；P2.16b 将发布、检视版本和下载接入桌面。普通浏览不会复制或哈希源文件。

## 桌面使用流程

源设备：打开“设备与信任 → 发布本机内容 → 准备发布”，选择本机已有 Agent 配置 JSON，确认共享目录，使用“选择文件/选择文件夹”选择共享内内容，点击“发布此路径的快照”。发布在后台生成不可变副本并校验，可取消；离开页面不终止发布，关闭软件会先取消并等待释放。完成后显示版本和发布时间。首次系统环境准备仍使用 P2.8 准备包，不由此入口安装服务或调整防火墙。

下载设备：在“传输任务 → 从设备下载 → 浏览共享目录”选择设备与授权共享。点文件名，或点文件/文件夹右侧“版本 → 查看”，检视已发布快照的类型、大小、发布时间和版本；点击“下载到…”选择本机目的路径，即按所选 manifest 创建真实任务。点击文件夹名称仍是进入目录，查看该文件夹版本需点击右侧“查看”。保存位置不能覆盖已有文件或目录。

未发布时显示源端发布指引；旧 Agent 没有路径索引能力时需要升级。下方“手工清单下载”继续支持已有 ID。只写共享不显示目录、也不能查询版本。选择结果有效十分钟，换设备/共享/目录或信任资料变化时需重新选择；取消本机保存对话框不会建任务。后台完成创建的任务始终显示在统一任务列表中。

版本详情固定一次检视的 manifest ID 和共享；即使源端随后更新索引，下载和持久化续传仍取旧快照。该选择不是远程发布命令，也不自动替换信任。

## 源端发布

使用配置中已存在的共享 ID 和共享内相对路径：

```powershell
hopsend-cli.exe publish-path --agent-config C:\HopSend\agent.local.json --share files --path "资料/报告.pdf"
```

同时支持文件夹和空文件。文件夹生成独立目录包，快照所占字节与目录列表大小含义不同。内容库不能位于正在发布的文件夹内。一个内容库同时只允许一个发布操作；遇到忙提示稍后重试。Ctrl+C 取消不会切换旧索引。发布耗时和空间随文件大小增长，所有者应确保磁盘容量充足。

返回相对路径、`manifest_id`、`content_id`、`size_bytes`、`payload_kind`、`published_at`。源文件发生改变时需要再次显式发布；正在进行的下载仍固定旧版本，不自动切换。

## 客户端查询

```powershell
hopsend-cli.exe path-index --url https://your-node:9443 --ca-cert C:\HopSend\ca.crt --token-file C:\HopSend\client.token --share files --path "资料/报告.pdf"
```

查询走受认证 HTTPS，文件内容继续由现有下载任务通过 SFTP 读取。`path_unpublished` 表示尚未发布，`index_stale` 表示索引/清单/对象不可用；请由源端重新发布，不按同名或同大小推断版本。只有上传许可的凭据不能查看索引。旧 Agent 缺少 `published_path_index` 能力时需要升级，或继续使用现有清单 ID 入口。

索引是“最后一次显式发布的快照”，不证明实时源文件仍与快照相同。客户端必须显示快照名称、大小、类型及发布时间并由用户选定，不能把目录实时元数据冒充已发布内容。版本完整性依旧由 manifest、块 SHA-256 和全文件 SHA-256 校验。

决定与边界见 [ADR 0014](adr/0014-published-path-index.md)，实际检查见 [P2.16a 验收](validation/P2.16a-published-path-index.md)与 [P2.16b 验收](validation/P2.16b-path-download.md)。
