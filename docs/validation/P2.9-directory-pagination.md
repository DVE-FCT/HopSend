# P2.9：目录分页与变化一致性验收

- 日期：2026-11-24
- 测试分支：`test/p2.9-directory-pagination`
- 基线：`6dfb17a`（已合并的 P2.7）
- 本地结果：通过；提交后仍需 PR、CI 和合并回读，不能以本地通过替代远端检查。

## 交付

1. 控制契约修订为 `0.3.0`，API 路径仍为 `v1`。目录请求加入 `limit`、`cursor`，响应加入 `next_cursor`、`has_more`；能力列表加入 `list_entries_paginated`。
2. 默认每页 100 项，最大 500 项。名称按 UTF-8 字节序排列；目录大小为零，链接与其他特殊项目继续过滤。
3. 游标由当前 Agent 实例签名并绑定共享、目录和元数据指纹。检测到变化返回 409 `cursor_stale`；非法、跨范围或旧实例游标返回 400 `invalid_cursor`。每页照常验证 HTTPS、Token 和共享权限。
4. Go 客户端提供 `EntriesPage` / `EntriesAll`；检查页长、范围、游标进展及名称顺序，拒绝重复或无进展。CLI 支持 `--limit`、`--cursor`、`--all`；完整聚合失败时不输出此前的部分目录。
5. README、使用说明、阶段规划、OpenAPI 与 [ADR 0010](../adr/0010-directory-pagination.md) 同步说明行为及边界。

## 实际验证

环境：Windows amd64；Go 1.27.4、Node 24.14.1、pnpm 11.25.0、Wails 2.17.1。测试目录、证书和凭据均在临时目录生成，不进入源码。

| 验证 | 实际结果 |
|---|---|
| 真实 HTTPS、1005 个文件、173 项/页 | 6 页读取，名称严格递增，去重后数量 1005，逐项检查全部预期名称；无遗漏/重复 |
| 默认页长与最大页长 | 分别返回 100 和 500 项，并给出续页游标 |
| CLI `--all --limit 500` | 聚合返回 1005 项，末页 `has_more=false`、`next_cursor` 为空 |
| 新增、删除、重命名、大小变化、修改时间变化 | 分页后旧游标均返回 409 `cursor_stale`；从第一页重读成功 |
| 中文空目录 | 返回空数组和结束标志，不返回 `null` 或伪续页 |
| 非法 limit、损坏/篡改游标、跨目录游标、非目录目标 | 返回对应的结构化 400 错误 |
| 同一目录授权为两个共享 | 仍拒绝跨共享复用游标 |
| 同一 TLS/Token/目录配置重建 Agent | 新实例拒绝旧游标；未关闭 TLS 校验 |
| 已取消请求 | 客户端返回 `context.Canceled` |
| 模拟远端重复项目、重复游标、空续页、错误范围、409 | 客户端在第二页失败，拒绝部分聚合结果，不继续循环 |
| 编译后的 Agent / CLI 独立进程 | 经真实受认证 HTTPS 按 500 项/页读取 1005 项，共 3 页，并逐项检查名称 |
| 既有认证、目录越界与链接、下载、上传、恢复等测试 | 全量 Go 测试通过 |

## 范围与未测事项

- 本阶段是 Agent / Go 客户端 / CLI 的独立交付，不引入 P2.8 未合并的配对和驻留改动，不新增桌面目录浏览界面。
- 当前目录枚举不是事务快照；并发变化检测基于元数据，无法保证发现所有竞态或保持相同元数据的内容替换。内容身份继续使用不可变 manifest 和 SHA-256 校验。
- 每页重新扫描并排序元数据，扫描和聚合最多 100000 项。此次实测规模为 1005 项，未测 100000 项边界的耗时、内存或极端并发性能；目录包传输的 10000 项限制保持独立。
- 本阶段未在第二台物理电脑更新 Agent 或执行新增分页接口的现场验收；验证使用本机真实 TLS 和独立进程。未新增原生 UI 点击、第三台干净系统安装或物理故障验收结论。
- 旧客户端使用严格 JSON 解码，不能承诺兼容新增响应字段。部署时同批升级 Agent 与客户端，调用方必须处理 `has_more`。已生成的 preview.13 准备包不自动获得此次源码改动。

结论：目录分页子阶段的本地完成条件已达到。远端 CI 与合并状态以对应 PR 为准；P2.8 未覆盖的现场条件继续单独记录。
