# P2.3 文件夹、路径和异常验收

日期：2026-11-23；分支：test/p2.3-folder-transfer。

## 交付

目录包包含空目录、相对路径、文件尺寸和 SHA-256 索引，manifest 增加可选 payload_kind=folder；复用既有分块/SQLite/确认上传。
CLI publish/upload 自动识别文件夹，下载按清单自动安全展开；桌面增加文件夹选择。整个目录核验、逐文件 Sync 后同卷禁止覆盖发布，不合并已有同名目录。
拒绝越界、盘符/ADS、反斜线、Windows 保留名称、大小写重复、链接/重解析点与 TAR 非常规条目；校验索引必须与实际包内容一致。
目录包缓存保留用于恢复和完成对账，空间与保留行为见 docs/15-folder-transfer.md。

## 自动与真实 Windows 异常检查

- 不同尺寸文件、空文件、空目录、中文以及超过 260 字符的层级路径，经实际 HTTPS/SFTP 下载和接收端确认上传，逐条路径、尺寸和哈希一致；重开完成任务可以对账。
- 恶意 TAR 路径越界、符号/硬链接、大小写冲突、重复项、错误哈希、缺失/过大索引不能发布正式目录。
- 原始目录打包后修改不改变已有包；正式目录被改后不能继续报告正确。
- 在 publishing、重命名之后、completed 附近实际退出子进程，重启后重新核验并恢复完整目录。
- 真实 Windows junction 被拒绝打包和作为目标祖先路径使用。
- 真实独立临时目录的只读 NTFS ACL 阻止下载，不发布目标；测试结束恢复原测试目录写权限，无系统目录 ACL 改动。
- 磁盘容量不足检查使用真实卷剩余空间与合法超大清单；不分配正式目标。真实物理磁盘写满未执行。

已执行完整 Go 检查、工具链、前端类型与 Vite、实际 Wails production 构建；文档基线与最终差异在提交前检查。

## 两台设备

第二台保持手机移动数据热点，经 SSH 部署目录版本的 CLI/Agent，独立计算程序 SHA-256。
远端发布混合样本：常规数据文件、中文文本、空文件和多个空目录，目录包为 271,360 字节。
客户端下载并自动展开后，以独立远端遍历/Get-FileHash 和本机遍历/SHA-256 比较完整清单；再将该目录上传回独立 inbox，新目录的全部相对路径、空目录、文件尺寸和哈希再次一致。
实际 Wails 桌面窗口通过“选择文件夹”发起上传，接收端确认完成；独立 SSH 遍历接收目录，与 CLI 已验证的目录清单逐项一致。
部署命令曾因中继延迟在返回前超时；回读核实程序哈希、源样本和已发布 manifest 后继续，没有把命令超时直接当作部署成功。

## 边界

本阶段是目录包整体续传，不是单文件增量同步。保留包缓存尚无自动回收；不宣称物理断电/写满验收。
现有同名文件夹一律拒绝，不擅自合并用户文件。标准用户目录下临时 Agent 用于现场测试，结束后停止。
`nCI 首轮发现运行器额外组权限使只读测试夹具仍可写；改为仅对独立测试目录添加当前用户的显式写入拒绝，并先验证普通写入返回无权限。结束时移除拒绝并恢复测试目录权限；不跳过权限验收。
