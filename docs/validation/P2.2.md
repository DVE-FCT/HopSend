# P2.2 接收端确认上传验收

日期：2026-11-23；分支：test/p2.2-confirmed-upload。

## 交付与验证

- 控制 API 增加创建/查询上传会话、确认块和 finalize；更新 OpenAPI 和共享 Go 类型。
- 共享 writable 与身份 upload_share_ids 双重授权；会话绑定认证身份和幂等请求 ID，SSH 文件权限独立。
- SQLite v2 保存接收会话与确认块，v1 事务迁移保留既有下载行；发送端快照、任务记录和原版本恢复。
- SFTP 写已分配暂存范围，接收端重新读取哈希、Sync 后确认；全部块后完整哈希并禁止覆盖发布。
- CLI upload 及 resume/control 复用共享 Manager；桌面添加真实上传入口和方向标识。
- 查询恢复与 finalize 的磁盘校验使用单独十分钟控制请求期限，不被普通五秒响应头超时截断。

本机真实 HTTPS/SFTP 集成已通过：正确上传、接收端字节一致、幂等重取会话与完成对账；未确认、未写入、坏块和错误全文件哈希不发布；已记录坏块重核验修复；只读共享拒绝上传；其他身份拒绝访问会话；请求 ID 不可绑定其他目标；容量不足在分配超大文件前返回 507；已有正式目标保持原字节。
实际关闭上传中的 TCP 连接，网络重试后以接收端确认块恢复并完成。确认事务成功后丢弃客户端 ACK，重启发送用例仍复用接收端已确认块。
在接收端 publishing、已建立正式名但未移除暂存/提交完成的边界，关闭并重建 Agent 与数据库连接，查询通过完整哈希与文件身份对账，状态 completed 且暂存名移除。

## 两台 Windows 实测

第二台仍使用手机移动数据热点；通过经验证 SSH 部署压缩的临时新 Agent，展开后核对可执行文件 SHA-256。
在原只读共享之外建立普通账号自己的临时 inbox，配置对应 API 上传授权；未开放额外端口或更改系统服务。

CLI 上传 1 MiB 实际文件，经接收 Agent 确认和发布后返回成功；随后使用独立远端 Get-FileHash 和文件长度复验，与发送源 SHA-256 一致。
在实际 Wails 窗口选择上传入口、同一 1 MiB 源和独立目标文件名，完成真实上传；界面显示已完成和接收确认块，远端再次独立读取哈希与长度一致。
本阶段两设备样本为 1 MiB，不把它写成大文件上传性能结论；大文件下载及偏移正确性见 P1。
