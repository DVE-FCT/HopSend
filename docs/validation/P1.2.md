# P1.2 SQLite 持久化与重核验续传验收

日期：2026-11-23；分支：test/p1.2-durable-resume。

## 交付与自动验证

- Journal 接口与 SQLite v1 迁移；任务保存原 manifest、路径、源配置引用、阶段状态和已确认块。WAL、FULL 同步及外键配置实际查询验证。
- 确认顺序为写入、长度/哈希验证、文件 Sync、SQLite 事务确认、进度通知；数据库失败不增加有效进度。
- 每个目标使用跨进程内核锁；进程退出释放句柄，持久锁标记不删除。
- 重启先重读已记录块：损坏、截短、缺失暂存均撤销无效确认并补传，不把预分配长度当成已完成证明。
- 全文件校验、publishing、禁止覆盖重命名、completed 分开持久化；目标与暂存同时存在时拒绝冒认目标。
- CLI download 自动保存，tasks 查看摘要，resume 使用同一数据库和原版本恢复。

独立子进程分别在 written、synced、confirmed、publishing、renamed、completed 六处直接退出，恢复结果和原文件逐字节一致；确认块数符合各边界，未提交事务退出后回滚。
另有真实双进程争抢目标及杀死旧进程后重新取得锁测试；已记录坏块的实际源读取范围证明完好确认块没有重复下载。
外部同名文件、发布前同内容竞争文件和发布后被改文件均不会被覆盖。

已执行格式检查、go vet、全套 Go 测试、CLI/Agent 构建、固定工具链诊断、文档基线检查。追加读取范围断言后，相关进程恢复测试单独复跑通过。
SQLite 加入后，构建两个程序的进程测试在冷编译时超过旧 45 秒预算；现构建预算 120 秒，HTTPS 就绪仍为 10 秒，全套测试预算 240 秒。

## 两设备大文件复验

已通过：5 GiB＋17 字节（5,368,709,137 字节）、161 个逻辑块；实际 CLI 确认 8 块后被强制结束，数据库保留 8 块确认。
修改其中第 0 块的实际暂存字节并同步后，启动全新的 CLI resume。引擎只复用 7 个完好块，损坏块和未完成块重新下载；161 块及最终全文件验证通过，数据库状态 completed，暂存文件移除。
验收脚本最后独立重读目标，完整 SHA-256 与源端、原清单及引擎结果一致。源端临时 Agent 已停止。
数据库源配置也经实际检查，仅含文件路径引用，不含本设备 Token 或 SSH 私钥内容。现场证据保存在本机忽略目录，公共记录仅保留脱敏结论。

## 边界

现场网络仍为同一局域网的 Tailscale 直连。不同宽带、显式暂停/取消和自动网络重试在 P1.3 验收。
进程退出和事务边界故障注入不等同物理断电。没有运行 race detector，不宣称通过该检查。
运行配置、数据库、凭据、大文件及完整设备记录均留在忽略目录；公开记录不含设备身份或账号。
