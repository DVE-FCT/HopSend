## Git 整理的证据

四处 UI 改动从 main 携带至本阶段测试分支，main 没有新增业务提交。四个旧 stash 均先归档为原生 bundle，在独立仓库读取相同对象并执行严格对象校验，包含第三父提交中的未跟踪源码。P2.8 当前 323 个源码文件另外形成完整恢复快照；树与当前文件一致，当前分支/文件/索引状态未改变。快照仅在仓库外保管，不作为已验收阶段提交，不推送。

按对象 ID 动态确认后清理四条旧 stash，列表为零，两个活动工作树状态保持不变。归档清单、SHA-256、UI 等价树及恢复说明保留在本机 maintenance-20261126 输出目录，不把个人绝对路径或私密工作内容提交。P2.8 原工作树和被忽略运行资料保留，不将旧 stash 重复 pop 到其上。

提交/合并继续采用“规范中文阶段提交 → PR → CI → 合并标题单独区分 → 回读复验”。旧测试分支只在确认已合并、无未保存工作且工作树不占用后清理；main、最近阶段和 P2.8 活动分支保留。PR/CI、最终分支清理及 main 干净状态以本阶段 PR 和本机终态记录为准。
