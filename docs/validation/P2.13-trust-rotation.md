# P2.13：显式凭据轮换验收

- 日期：2026-11-25
- 分支：test/p2.13-trust-rotation
- 基线：228c5fc（P2.12 已合并）
- 范围：Go 资料版本发布、桌面轮换桥接、显式核对 UI 和旧任务引用保持。

## 交付与设计

设备卡片“轮换信任”进入已有向导的轮换模式，固定设备原请求，不创建替代设备。可重新导出原公开请求；新回应须绑定原请求、本机私钥并经过近期检视及两项独立指纹核对。最终确认后调用 RotateDeviceTrust，再按原 manage_agent 选择验收。连接失败只反馈结果，不偷偷接受或回退其他身份。

Go 使用不可变 paired-<摘要>/ 版本，首次 paired/ 及原私钥不移动。资料完整发布后，以旧设备快照为前提原子更新 devices.json；保留设备 ID、用户名称和托管选择。SQLite 任务 Source 和状态均不修改。普通导入仍拒绝信任冲突，也不能把轮换过的设备恢复到旧引用。重置健康观察代次，禁止旧凭据的在途 health 结果刷新新凭据的状态点。

## 实际验证

环境：Windows amd64，Go 1.27.4、Node 24.14.1、pnpm 11.25.0、Wails 2.17.1。定向 Go、前端七项生产流程测试、TypeScript/Vite、gofmt、go vet、无缓存全量 Go 测试、严格工具链诊断、CLI/Agent 和实际 Wails 构建均通过。

```powershell
go test -v -count=1 ./apps/desktop ./internal/pairing/material
node --test scripts/check/package-flow.test.mjs scripts/check/pairing-lifecycle.test.mjs
./scripts/check/check-go.ps1 -StrictDoctor
./scripts/build/build-desktop.ps1
git diff --check
```

| 项目 | 结果 |
|---|---|
| Go 资料轮换 | 原 paired/ 五个资料文件逐字节保持，新配置引用独立版本，私钥路径不变 |
| 普通导入边界 | 新 Token/CA/SSH 主机密钥仍返回 trust_conflict，不覆盖；桌面普通导入不会重置新版引用 |
| 核对与绑定 | 未检视、错误可信指纹、其他设备 ID、缺少原信任、取消和忙锁全部拒绝 |
| 幂等与损坏 | 相同材料的 ZIP/JSON 重编码仍复用版本；已发布新版 Token 被改变时拒绝覆盖 |
| Windows 权限 | 新目录及 CA/Token/known_hosts/connection/device 文件只有当前账号和 SYSTEM 授权 |
| 真实写入失败注入 | 对 devices.json 持独占 Windows 句柄，迫使原子替换失败；内存 Device 与磁盘快照均保持原值；释放句柄后重试成功 |
| 稳定设备身份 | 轮换后设备数量仍为 1；ID、本机私钥、用户名称、非托管选择不变；旧快照提交被拒绝 |
| 任务历史 | 创建真实 SQLite 暂停任务，比较轮换前后 ID、状态及原 Source 字节，完全相同；原 CA 路径内容保持不变 |
| 观察失效 | 前端在同 ID 轮换后丢弃旧代次的在途观察；重新观察才可发布结果 |

## 边界

本机测试不冒充第二台设备真实重装、远端凭据撤销、CA 到期续签或原生鼠标交互。未测试物理断电。旧资料保留，没有自动迁移历史任务或自动清理；旧授权已被远端撤销时，历史任务可能无法续传。本阶段不轮换本机 SSH 私钥，也不改动 P2.8 未验收的源端环境脚本。

设计和边界见 [ADR 0013](../adr/0013-versioned-trust-rotation.md)。PR/CI 与合并结果以本阶段 PR 为准。
