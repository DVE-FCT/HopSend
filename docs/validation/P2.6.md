# P2.6：桌面可用性与后续规划

日期：2026-11-23。测试分支：`test/p2.6-desktop-usability`。基线：P2.5 main。

## 交付

- 主题化侧栏、统一字重、7px 状态进度条、弹性任务标题、可筛选的待处理统计和 SVG 空态。
- 独立可关闭的错误/通知、准备中的旋转与文字反馈、只读 HTTPS 设备观察和时间、设备模态抽屉、任务定位与活动记录跳转、会话记录折叠、实际版本与任务轮询时间。
- Wails 原生拖入路径选择（不自动上传）；完成下载可通过 Windows Shell 定位目标，不执行文件。后端从持久任务取目标，拒绝上传、未完成、相对/失效路径和链接组件。
- P3 前增加 P2.7 单源基线、P2.8 分发与用户登录驻留；P4.1 扩展回归及受控磁盘/关机边界。补平台 ADR、缓存/多接收端上传边界，以及可区分的合并标题规则。

## 真实 Windows 交互

使用实际 Wails 生产构建、已有任务库和已配对第二台 Windows，没有注入模拟任务或伪造健康状态。

| 场景 | 观察结果 |
|---|---|
| 浅/深色任务、设备、记录和诊断 | 页面内容分开显示；侧栏深色更暗；实际版本为 0.1.0-dev，页脚随成功任务读取更新 |
| 完成任务 | 64 MiB 真实历史下载显示绿色 100% 进度；上传项无本机打开按钮 |
| 打开文件夹 | 点击已完成 64 MiB 下载，在资源管理器打开 outputs 并选中对应中文文件，未打开/执行内容 |
| 活动记录跳转 | 记录显示任务名；点击返回任务列表并滚动到关联下载；进入时边框高亮，本次会话操作默认折叠 |
| 设备健康与过期 | 真实 HTTPS 可达、Agent 版本与观察时间；一分钟后文字变为“上次 HTTPS 可达”，状态点回到灰色。查看卡片仅调用健康接口 |
| 准备并验收 | 点击后出现面板及按钮旋转反馈；SSH/证书/API/共享和 32 KiB SFTP 写入回读均通过；已有 Agent 复用 |
| 设备抽屉 | 编辑时名称获得焦点，Escape 关闭并恢复入口；空白新增被拒绝，没有添加无效设备 |
| 通知并存 | 准备成功通知与空白设备校验错误同时显示，各自可关闭 |
| 诊断加载与耗时 | 旋转加载面板区别于未诊断空态；实际直连观察，HTTPS/SSH 身份通过；未填清单的文件读取层标“未执行”，耗时为“—” |

首轮交互发现：长抽屉底部保存失败后，顶部错误可能在视野外；已增加错误区域焦点，将失败原因滚入视野，并锁定模态期间背景滚动。最终 EXE 重开后再次从空表单底部保存，确认滚回可见错误、没有创建无效设备。观察请求增加对象身份检查，避免保存新配置后被旧请求结果覆盖。

## 边界与未测项

- 原生跨窗口拖放：Wails 选项、注册/注销、目标样式及单项/多项分支已接入并构建。当前 Windows 自动化工具拒绝跨越源窗口边界的拖动，未获得从资源管理器实际拖入成功的证据；单文件/文件夹、多项拒绝及准备期间拖入仍待人工现场验收。现有文件/文件夹选择按钮继续可用，不把模拟 DOM drop 冒充原生验证。
- 未在物理 4K 屏幕、屏幕阅读器、管理员/非管理员不同完整性级别拖放和新 Windows 镜像上验收；状态颜色同时有文字，保留 reduced-motion 规则。
- 本阶段未再次传输 5 GiB、注入实际断电/物理磁盘满，也未实现多源、局部缓存、计划任务、系统服务或安装器。网络观察只代表当次路径，不冒充热点测试或性能基准。
- `font-weight: 650` 是合法现代 CSS 数值，本轮改成 600 是视觉统一；没有把原建议中的规范判断写成浏览器缺陷。

本阶段的桌面可用性、真实控制与定位交互以及构建检查已验证，原生拖放明确保留现场验收限制。后续性能/分发阶段仍为规划，不因文档已写而计为实现。
