# P2.5 已配对设备准备与自动恢复验收

日期：2026-11-23；分支：test/p2.5-device-readiness。

## 触发问题

P2.4 验收后临时 Agent 停止，用户只能看到 HTTPS 9443 超时，而 Tailscale/SSH 仍通过。再次通过 SSH Start-Process 返回了 PID，但会话退出后进程不存在，回读显示无监听。瞬间 PID 不能证明实际使用就绪。

## 交付

明确启用托管的配对设备，在保存后执行准备，下载/上传/诊断之前自动验收；传输尝试前检查健康状态并恢复缺失 Agent。使用原 SSH 主机信任、HTTPS 证书及 API 授权，不重新建立或绕过信任。由配套 Agent 的本机 SHA-256 定位远端版本，随机暂存上传、核验后禁止覆盖发布，再通过认证执行会话启动。

步骤包含真实 SSH/SFTP、Windows x64/原配置、Agent 程序与启动、HTTPS/共享授权、32 KiB SFTP 写入回读和 SHA-256；所有步骤通过才报告就绪。构建桌面时同时归集配套 Agent，缺少配套程序则在需要部署时明确失败。保留手动管理设备兼容性。

## 实际两设备验收

- 经已核对主机身份的 SSH 回读，远端无旧 Agent 和 9443 监听；CLI device-prepare 自动部署程序、核验远端哈希、启动并取得 ready=true、managed=true，HTTPS 和 32 KiB 数据校验全部通过。
- 停止这次部署的受控 Agent，实际桌面点击“准备并验收”，自动恢复并显示六项通过和“设备已就绪”。原证书、凭据及共享授权沿用，无远端人工启动操作。
- 再次停止受控 Agent，直接调用与桌面共享的真实 Manager 下载入口，不预先调用准备按钮；自动准备后完成 4,194,304 字节下载。本机独立重读 SHA-256 与可信源版本一致：0219c9ab34165ac1a2c2f232524f3fe96679ae81b94748f38f74e9692ec90d51。
- 本机现有已授权设备引用开启自动准备，原 devices.json 已备份；机器路径与凭据只留忽略目录和本机用户目录。

## 自动与平台验证

真实 SSH/SFTP 准备文件测试验证新建、禁止覆盖、读回哈希、删除与 exec 取消；取消后不误报成功。实际 Windows PowerShell 验证含中文、引号、美元符号路径作为 JSON 数据传入，拒绝相对配置路径和错误程序哈希；正确暂存程序才发布。测试使用独立 LOCALAPPDATA，不修改系统服务或防火墙。

完整 Go/前端/Wails 和阶段基线检查在提交前执行。所有失败均先修正夹具或实现后重测；未删除验证来通过 CI。

首轮 Windows CI 的首次 PowerShell 子进程超过夹具 15 秒上限；将 LOCALAPPDATA 的隔离移至脚本运行时，保留正常 PowerShell 启动环境，并将单次平台脚本验收上限设为 45 秒。路径、哈希、禁止发布坏程序等实际断言均保留，修正后重新验证。

后续 CI 暴露运行器同时使用 Windows 短路径和长路径：准备脚本返回的完整路径与 Go 临时目录文本不同，但指向同一文件。夹具改为使用 os.SameFile 核对真实文件身份，保留中文、引号与美元符号路径，不把文本差异误判成配置被更换。

## 边界

这是已配对节点的按需部署/启动和网络验收。首次 Tailscale 登录、OpenSSH 安装、管理员防火墙及证书/密钥授权仍需设备所有者完成；尚无通用图形安装器或开机自启 Windows 服务，不宣称新电脑零授权即连。

进程生命周期由桌面持有的认证 SSH 执行通道管理，关闭软件释放管理连接。Windows OpenSSH 是否马上结束子进程取决于平台，每次连接均以真实健康探测为准，不能依赖旧进程或旧就绪快照。程序缓存暂无自动清理；中断部署可能保留随机暂存文件，正式版本不会发布半成品。
