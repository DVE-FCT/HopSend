## 本阶段交付

Wails `App` 暴露 `PairLocalIdentity`、`PairCreateRequest`、`PairInspectReply`、`PairImportReply`，TypeScript 声明与真实 Go 方法匹配。四步向导显示本机 Tailscale IP、生成公开请求、选择/拖入回应、展示指纹并要求手填可信值与勾选；导入绑定本机原请求/私钥后自动保存设备，真实网络验收仍通过设备卡片的“准备并验收”执行。

配对包使用已有三项回应材料，格式为 `.hopsend-pair`。导出受限、私密且不覆盖已有文件；预览明确返回 `trust_verified=false`，不直接建立信任。跨页或拖入更换回应后清除确认。原生拖放由 App 统一注册，配对包不会被上传组件误选；普通 ZIP 只有经显式选择才进入配对。

## 实际验证

环境：Windows amd64；Go 1.27.4、Node 24.14.1、pnpm 11.25.0、Wails 2.17.1。

| 项目 | 结果 |
|---|---|
| 桌面方法生产调用测试 | 使用真实 App、Go 资料核心、SQLite Manager 和临时资料；生成请求 → 检视 → 可信指纹导入 → 回读设备及连接引用，通过 |
| 本机地址绑定 | 显示地址与生成请求的实际 Tailscale 状态不一致时拒绝；测试的 Tailscale 状态来自受控适配器，不冒充现场网络 |
| 检视与错误指纹 | 检视不生成 paired/ 或保存设备，`materials_verified=true`、`trust_verified=false`；错误 SSH 指纹不导入也不保存设备 |
| 重试与文件变更 | 重复完成仅保存一台稳定 ID 的设备；回应在检视后变化时拒绝，要求重新检视 |
| 配对包核心 | 预览不授权、原请求重导出、包内容与上限、额外尾部载荷丢弃、已有目标不覆盖、暂存清理均通过 |
| 相同资料重新编码 | device.json 字段相同而 JSON 排版不同可重试；原有更换 Token / 私钥不匹配拒绝测试继续通过 |
| Windows ACL | 导出的私密配对包仍只授予当前账号与 SYSTEM；原有私钥/Token/缓存权限检查继续通过 |
| 编译 CLI 互通 | Go 密钥由 Windows OpenSSH 读取，WinPS5.1 生成旧 ZIP，再执行 inspect-request/preview/package/inspect/import；ZIP 和 .hopsend-pair 返回相同固定配置，公开输出不含私钥或 Token |
| 前端流程测试 | 3 项通过：配对包优先且混合拒绝；未确认/无预览/错误指纹不调用导入；明确匹配后只调用一次并传入核对值 |
| 前端和桌面构建 | TypeScript、Vite 和实际 Wails Windows 构建通过 |
| 严格全量检查 | gofmt、go vet、无缓存全部 Go 测试、CLI/Agent 构建、固定工具链诊断、Git 差异检查通过 |
