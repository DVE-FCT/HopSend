# P2.18：共享快照的独立批次上传

- 日期：2026-11-27
- 分支：test/p2.18-batch-upload
- 基线：26c32da（P2.17 合并）
- 状态：本机实现与验证完成，按 PR/CI 流程集成；物理现场边界如下

## 交付范围

控制契约修订 0.6.0：显式 `manifest_scope: source_snapshot` / `upload_source_snapshot` 能力，让相同源 manifest 可发送到不同授权共享；缺省模式保留原 share_id 绑定。客户端检查能力、响应 scope 和版本，Agent 独立验证目标权限，会话与恢复持久化 scope。

SQLite v4 保存批次和接收队列，升级前一致备份。创建请求键幂等，一次固定源快照，最多32目标/16未结束批次；准备串行且检查容量，批次最多2个活动接收任务，全部上传共享全局4/同配置SSH节点2个活动块。停止等待 worker 后释放完成/取消的引用；失败/暂停保留，零引用只作清理候选。

桌面包含一发多收面板、各接收目录、批次分组、逐台进度和逐台/批次暂停继续取消。关闭先停调度并等待任务；重开保留暂停，不重复发送已完成接收端。

## 已运行结果

1. 定向 Go 测试通过：真实本机5个独立 TLS Agent/SFTP 接收端，两个不同授权共享成功、一个无上传权限失败、一个同名冲突失败、一个关闭 HTTPS 监听后离线失败。成功端收到同一固定原始字节、同一 manifest/对象；源之后修改未混入，冲突文件保留。
2. 独立确认/引用持久化通过：两个失败仍保留引用，取消后归零；关闭/重建批次管理器保留成功/取消状态。默认 share 不匹配拒绝，显式模式不扩大目标权限。
3. 故障夹具检查通过：旧 Agent/错误 API 版本在 POST 前拒绝；scope 响应变化及未知状态 scope 拒绝。
4. 调度适配器检查通过：3接收任务只启动2个；批次暂停等旧 writer 退出，逐台取消不动其他目标；关闭/重开不自动启动。失败独立，成功端不会因批次恢复重发。独占队列锁和全局/节点块预算及释放通过。
5. SQLite v3→v4 保留原父目录身份；一致备份可读取原 schema 和 WAL 已提交数据。既有 v1/v2 迁移定向回归通过。
6. TypeScript/Vite 与5项新增前端状态测试通过：重复点击、丢失回应重试键、超量/重复目标拒绝、目标改变的新请求身份，以及排队/会话前失败任务与传输库合并统计不重漏。
7. 不同 manifest 的相同内容共用对象引用，逐个取消后2→1→0且副本仍保留；超量目标在准备前拒绝、禁止快照库位于发送目录内、目录准备可取消。
8. Playwright 实际 Vue 页面在演示桥接下通过两目标独立目录、只写无读取调用、批次与逐台控制、成功不变、显式新批次、任务总数/筛选和1080px明暗布局检查。截图在仓库外 `outputs/maintenance-20261126/output/playwright/p218-batch-{light,dark}.jpg`。界面检查没有发起真实传输。
9. 全量未缓存 Go、gofmt/vet、四项严格工具链诊断通过；首次严格检查未找到 Wails PATH，使用工程既有固定版本后重跑通过。实际 Wails Windows EXE 构建及文档/钩子基线通过。新增离线与准备边界在最终定向回归中复验，PR CI负责最终提交快照。

## 验收边界

以上网络传输为真实本机 TLS/SFTP 端点，调度停止边界另有可控内核适配器；不冒充多台物理 Windows 或原生 Wails 文件对话框验收。未进行第三台干净 Windows / P2.8 完整现场，仍阻塞 P3.x 合并。未进行真实物理断电、专用小卷写满或批次大流量压力矩阵；不以估算磁盘预算声称预留空间或 VSS 事务快照。目录源是在显式准备期打包校验，不保证跨文件系统时刻的一致性。

无广播会话、自动垃圾回收、历史归档界面或跨进程总带宽协调。初始预算后续根据 P4 性能回归评估。P2.8预览整合和干净系统现场继续单列；本机未运行 race detector，不将普通测试声称为竞争检测。
